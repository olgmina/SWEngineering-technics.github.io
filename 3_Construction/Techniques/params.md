# Практика. Настройки приложения

## Цель работы

Познакомиться с понятием настроек приложения, исследовать способы их хранения и реализовать настройки в GraphEditor.

В ходе работы необходимо:

- разобраться, чем настройки отличаются от данных приложения;
- исследовать настройки, используемые в среде разработки;
- рассмотреть различные способы хранения настроек;
- выбрать способ для GraphEditor;
- реализовать изменение и сохранение настроек;
- проверить их влияние на создаваемые объекты.

# 1. Что такое настройки приложения

**Настройки приложения** — это параметры, которые определяют поведение или внешний вид программы и могут изменяться без изменения исходного кода.

Например, в графическом редакторе настройками могут быть:

- цвет рабочего поля;
- цвет заливки новых фигур;
- цвет границы;
- толщина границы;
- наличие тени;
- отображение сетки.

Настройки являются частью более широкого понятия **конфигурации приложения**.

Конфигурация может содержать параметры, определяющие работу программы в конкретной среде, например адрес сервера, путь к файлам или режим работы. Не все конфигурационные параметры пользователь изменяет непосредственно.

В данной работе рассматриваются именно **пользовательские настройки**.

### Настройки и данные приложения

Важно отличать настройку от данных, с которыми работает программа.

Например:

> Цвет заливки по умолчанию — настройка редактора.  
> Цвет конкретного многоугольника — свойство объекта рисунка.

Можно представить это следующим образом:

```text
Параметры приложения
        │
        ├── Настройки
        │     ├── цвет фона
        │     ├── цвет заливки
        │     └── толщина границы
        │
        └── Данные
              └── рисунок
                   ├── Point
                   ├── Circle
                   ├── Square
                   └── Polygon
```

# 3. Способы технической реализации

Настройки необходимо не только предоставить пользователю, но и где-то хранить.

Возможны различные технические решения.

## 3.1. Хранение в памяти программы

Настройки можно хранить в полях объекта:

```java
class Settings {
    Color fillColor;
    Color borderColor;
    double borderWidth;
    boolean shadowEnabled;
}
```

При запуске программы создаётся объект `Settings`.

**Преимущества:**

- простая реализация;
- не требуется работа с файлами.

**Недостаток:**

- изменения теряются после завершения программы.

Такой вариант подходит для временных настроек.

---

## 3.2. Файл Properties

Для хранения простых параметров можно использовать текстовый файл:

```properties
fillColor=WHITE
borderColor=BLACK
borderWidth=2.0
shadowEnabled=true
```

При запуске программа считывает значения из файла.

**Преимущества:**

- простой формат;
- настройки сохраняются между запусками;
- файл легко просмотреть.

**Недостатки:**

- значения хранятся как текст;
- преобразование в цвета, числа и другие типы выполняется программой;
- формат неудобен для сложных структур.

---

## 3.3. JSON

Настройки можно представить в виде JSON:

```json
{
    "fillColor": "#FFFFFF",
    "borderColor": "#000000",
    "borderWidth": 2.0,
    "shadowEnabled": true
}
```

**Преимущества:**

- структурированный формат;
- удобно хранить большое количество параметров;
- широко используется в программных системах.

**Недостатки:**

- работа с JSON требует дополнительных средств или библиотеки;
- реализация сложнее, чем для Properties.

---

## 3.4. Средства платформы

Можно использовать специальные средства Java или используемой библиотеки для хранения пользовательских настроек.

В этом случае необходимо обратиться к документации и определить:

- где хранятся данные;
- как выполняется запись;
- как выполняется чтение;
- какие типы данных поддерживаются;
- сохраняются ли настройки между запусками.

# 4. Сравнение способов хранения

Исследуйте не менее двух способов хранения настроек и заполните таблицу.

| Способ | Сохраняются после завершения | Сложность | Структура данных | Особенности |

| JSON | Да | Средняя | Структурированная | Удобен для сложной конфигурации |
| Средства платформы | Обычно да | Зависит от средства | Зависит от средства | Требует изучения документации |

# 5. Задание для GraphEditor

## 5.1. Добавьте настройки редактора

Реализуйте следующие настройки:

| Настройка | Назначение |
|---|---|
| Цвет фона | Цвет рабочего поля |
| Цвет заливки | Цвет заливки новых фигур |
| Цвет границы | Цвет границы новых фигур |
| Толщина границы | Толщина границы новых фигур |
| Тень | Включение или отключение тени |

Значения по умолчанию задаются программой.

---

## 5.2. Добавьте окно настроек

Пользователь должен иметь возможность открыть настройки GraphEditor и:

1. просмотреть текущие значения;
2. изменить значения;
3. применить изменения;
4. отменить изменения;
5. восстановить значения по умолчанию.

Внешний вид окна настроек выберите самостоятельно.

---

## 5.3. Используйте настройки при создании объектов

Проверьте работу настроек на примере создания новых объектов.

Например:

1. установить синий цвет заливки;
2. установить красную границу;
3. установить толщину границы 3;
4. включить тень;
5. создать многоугольник;
6. проверить его внешний вид.

После этого измените настройки и создайте ещё один объект.

Новый объект должен использовать новые значения.

**Уже созданные объекты изменять не требуется.**

---

## 5.4. Сохранение настроек

Выбранным техническим способом реализуйте сохранение настроек.

При запуске программы:

```text
Хранилище настроек
        ↓
     Settings
        ↓
    GraphEditor
```

При изменении настроек:

```text
GraphEditor
     ↓
  Settings
     ↓
Хранилище настроек
```

После перезапуска программы должны использоваться сохранённые значения.

Выполните следующие проверки.

| № | Проверка | Ожидаемый результат |
|---|---|---|
| 1 | Изменить цвет заливки | Новые фигуры используют новый цвет |

| 5 | Выключить тень | Новые фигуры создаются без тени |
| 6 | Отменить изменения | Предыдущие настройки сохраняются |
| 7 | Восстановить значения по умолчанию | Возвращаются исходные значения |
| 8 | Создать объект до изменения настроек | Объект сохраняет прежний внешний вид |
| 9 | Создать объект после изменения настроек | Объект использует новые настройки |
| 10 | Перезапустить приложение | Сохранённые настройки восстанавливаются |
