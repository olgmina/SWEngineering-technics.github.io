## Контекст задачи

Информационное представление системы определяет структуру хранимой и временной информации. Для небольшой системы это модель данных, включающая сущности, их атрибуты и связи. Правильно спроектированная модель данных обеспечивает целостность, производительность и масштабируемость системы.

## Формулировка

Разработайте информационную модель (модель данных) для вашей программной системы.

## теория и примеры

- **Сущность** — то, о чём система хранит данные (пользователь, заказ, продукт)
- **Атрибут** — свойство сущности (имя, дата, цена)
- **Ключ** — уникальный идентификатор сущности (ID)
- Используйте **глаголы** для определения связей («пользователь *создаёт* заказ»)

[Детально ERD](2_Design/Techniques/ERD_описание.pdf)

### 1. Выявление сущностей

На основе требований и сценариев использования выделите:

1. **Основные сущности** (объекты, о которых система хранит информацию)
2. **Атрибуты** каждой сущности (свойства, характеристики)
3. **Ключи** (первичные, внешние)

### 2. Определение связей

Определите связи между сущностями:

| Связь | Тип | Объяснение |
|-------|-----|------------|
| Сущность А — Сущность Б | 1:1 / 1:N / N:M | почему такая связь? |

### 3. Построение диаграммы

Постройте ER-диаграмму (или UML-диаграмму классов) модели данных:

- Сущности (прямоугольники)
- Атрибуты (внутри сущностей)
- Связи (линии с нотацией)

*Пример: [диаграмма последовательности](https://github.com/olgmina/SWEngineering-technics.github.io/blob/e8679238e19c82118510f8a239dfa5fc345eaccf/design/%D0%9F%D1%80%D0%B8%D0%BC%D0%B5%D1%80%D1%8B%20%D0%BF%D0%BE%D1%81%D1%82%D1%80%D0%BE%D0%B5%D0%BD%D0%B8%D1%8F%20%D0%B4%D0%B8%D0%B0%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%20%D0%BF%D0%BE%D1%81%D0%BB%D0%B5%D0%B4%D0%BE%D0%B2%D0%B0%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D0%BE%D1%81%D1%82%D0%B5%D0%B9.pdf)*

### 4. Нормализация*

Проверьте модель данных на соответствие нормальным формам (1НФ, 2НФ, 3НФ). Если есть нарушения — исправьте.

### 5. Составление описания

Опиши будущую БД по [шаблону](2_Design/Managment/desing_DB.md)

## Результаты

ER-диаграмма или UML-диаграмма классов

## Критерии оценивания

- [ ] Выделены все основные сущности (минимум 4)
- [ ] Для каждой сущности определены атрибуты (минимум 3 на сущность)
- [ ] Определены первичные и внешние ключи, cвязи между сущностями корректно типизированы
- [ ] ER-диаграмма отражает все сущности и связи
- [ ] Модель данных соответствует требованиям (не противоречит use case)
