# Матрица классификации требований

**Матрица классификации представляет собой табличный метод систематизации функциональных требований, и её цель — структурировать требования, выявить пробелы и исключить дублирование**

## Назначение матрицы

Матрица классификации позволяет одновременно решать несколько задач:

- группировать требования по категориям (модулям, функциям, областям);
- сопоставлять требования с ролями пользователей;
- выявлять пробелы (категории или роли без требований);
- обнаруживать дублирования.

## Структура матрицы

Матрица строится по принципу двумерной таблицы:

| Категория | Роль 1 | Роль 2 | Роль 3 |
|-----------|--------|--------|--------|
| Категория А | Требование A1 | Требование A2 | — |
| Категория Б | Требование Б1 | — | Требование Б3 |

**Пояснение:**

- Строки — категории требований (например, «Управление задачами», «Поиск», «Отчеты»)
- Столбцы — роли пользователей (например, «Пользователь», «Менеджер», «Админ»)
- Ячейки — функциональные требования с уникальными идентификаторами (FR-01, FR-02…)

## Правила формулировки требований

Каждое требование в ячейке матрицы должно соответствовать правилам:

| Правило | Неправильно | Правильно |
|---------|-------------|-----------|
| **Один глагол** | «Система должна создавать и редактировать задачи» | «Создать задачу», «Редактировать задачу» |
| **Проверяемость** | «Быстрый поиск» | «Поиск возвращает результат за < 1 секунды» |
| **Однозначность** | «Удобное управление» | «Пользователь может изменить статус задачи из списка в один клик» |
| **Атомарность** | «Админ управляет пользователями» | «Админ может создать пользователя», «Админ может заблокировать пользователя» |

## Порядок построения

Матрица классификации заполняется в следующем порядке:

1. **Определите категории** (3-7 штук) — это «срезы» функциональности системы
2. **Определите роли** — из ранее составленных сценариев использования
3. **Для каждой ячейки** решите: есть ли у этой роли требование в данной категории?
4. **Сформулируйте требование** по правилам (один глагол, проверяемость, однозначность)
5. **Пронумеруйте требования** (FR-01, FR-02…)

## Проверка полноты матрицы

После заполнения матрицы необходимо провести проверку:

| Проверка | Вопрос | Действие |
|----------|--------|----------|
| **Полнота** | Есть ли категории вообще без требований? | Добавить требования или удалить категорию |
| **Покрытие ролей** | Есть ли роль без требований? | Пересмотреть необходимость роли |
| **Дублирование** | Одно и то же требование в двух ячейках? | Оставить одно, указать список ролей |
| **Связность** | Каждое требование вытекает из use case? | Проверить трассировку |

## Пример матрицы

*Пример для системы управления проектами*

| Категория | Пользователь | Менеджер | Админ |
|-----------|--------------|----------|-------|
| **Управление задачами** | FR-01: Создать задачу | FR-04: Назначить исполнителя | FR-07: Удалить любую задачу |
| | FR-02: Редактировать свою задачу | FR-05: Изменить дедлайн | — |
| | FR-03: Изменить статус | — | — |
| **Поиск** | FR-08: Искать по названию | FR-09: Фильтр по исполнителю | FR-10: Полнотекстовый поиск |
| **Отчеты** | — | FR-11: Отчет по проекту | FR-12: Аудит действий |
