# SWOT-анализ спецификации требований

SWOT-анализ — это метод стратегического планирования, используемый для оценки **качества и полноты спецификации требований** (SRS). Название метода — акроним от английских слов Strengths, Weaknesses, Opportunities, Threats.


## Назначение SWOT-анализа в валидации требований

SWOT-анализ позволяет решать следующие задачи:

- выявить сильные стороны спецификации (что сделано хорошо);
- обнаружить слабые стороны (что отсутствует или плохо сформулировано);
- определить скрытые возможности (что можно улучшить или развить);
- предвидеть угрозы (риски, связанные с пробелами в требованиях).

## Расшифровка аббревиатуры

| Буква | Английский термин | Русский перевод | Что оцениваем в спецификации требований |
|-------|-------------------|-----------------|------------------------------------------|
| **S** | **Strengths** | **Сильные стороны** | Что в спецификации сделано хорошо, какие требования качественные |
| **W** | **Weaknesses** | **Слабые стороны** | Что отсутствует, плохо сформулировано, требует доработки |
| **O** | **Opportunities** | **Возможности** | Какие скрытые плюсы даёт текущая спецификация |
| **T** | **Threats** | **Угрозы** | Какие риски возникают из-за пробелов в требованиях |

## Структура SWOT-анализа для SRS

### Сильные стороны (Strengths)

*Внутренние положительные качества спецификации.*

| Вопрос для анализа | Пример сильной стороны |
|--------------------|------------------------|
| Что сделано хорошо? | «Все функциональные требования имеют уникальные идентификаторы» |
| Какие требования качественные? | «Для каждого нефункционального требования указана метрика» |
| Что облегчит разработку? | «Есть приоритеты требований (MoSCoW)» |
| Какие разделы проработаны лучше всего? | «Подробно описан интерфейс пользователя» |

### Слабые стороны (Weaknesses)

*Внутренние недостатки спецификации.*

| Вопрос для анализа | Пример слабой стороны |
|--------------------|-----------------------|
| Что отсутствует? | «Нет требований к обработке ошибок» |
| Что сформулировано плохо? | «Много стоп-слов: "удобный", "быстрый", "несколько"» |
| Какие требования противоречивы? | «ФР-05 и НФР-02 противоречат друг другу» |
| Какие разделы проработаны хуже всего? | «Раздел "Отказы" содержит только общие фразы» |

### Возможности (Opportunities)

*Внешние или скрытые положительные факторы, которые можно использовать.*

| Вопрос для анализа | Пример возможности |
|--------------------|--------------------|
| Какие скрытые плюсы дают требования? | «Требование к API позволяет в будущем сделать мобильное приложение» |
| Что можно улучшить с минимальными усилиями? | «Добавить диаграмму потоков данных для наглядности» |
| Какие современные практики можно применить? | «Заменить расплывчатые требования на критерии приемки в формате Gherkin» |
| Что ускорит разработку? | «Уже есть шаблон для тест-кейсов» |

### Угрозы (Threats)

*Внешние или внутренние риски, связанные с пробелами в требованиях.*

| Вопрос для анализа | Пример угрозы |
|--------------------|---------------|
| Какие риски не учтены? | «Нет требований к бэкапам — потеря данных» |
| Что может привести к срыву сроков? | «Непроверяемое требование "быстрый поиск" — разработчик и заказчик могут не договориться» |
| Какие противоречия опасны? | «Конфликт между производительностью и безопасностью не разрешён» |
| Что может вызвать недопонимание с заказчиком? | «Много субъективных оценок: "удобный", "красивый"» |

## Порядок проведения SWOT-анализа

1. **Изучите спецификацию требований** целиком
2. **Заполните квадрант Strengths** — найдите 3-5 сильных сторон
3. **Заполните квадрант Weaknesses** — найдите 3-5 слабых сторон
4. **Заполните квадрант Opportunities** — найдите 2-3 возможности
5. **Заполните квадрант Threats** — найдите 2-3 угрозы
6. **Сформулируйте выводы и рекомендации**
