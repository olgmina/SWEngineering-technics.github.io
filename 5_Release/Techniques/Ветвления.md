# Практика. Ветвление и слияние в Git

## Цель

Научиться использовать ветки Git для параллельной разработки функциональностей проекта.

В рамках практики работа выполняется на проекте **GraphEditor**, первый инкремент которого предусматривает создание растровых элементов:

- точки;
- круга;
- квадрата.

Каждая функциональность разрабатывается в отдельной ветке.

Основная схема работы:

```text
Задача
  ↓
Ветка
  ↓
Разработка
  ↓
Commit
  ↓
Pull Request
  ↓
Code Review
  ↓
Merge
```

---

# Упражнение 1. Создание репозитория

Создайте Git-репозиторий проекта `GraphEditor`.

Добавьте в проект:

```text
README.md
.gitignore
```

В `README.md` укажите:

- название проекта;
- назначение программы;
- текущий инкремент;
- краткое описание реализуемых возможностей.

Выполните первый commit.

Проверьте состояние репозитория:

```bash
git status
```

Просмотрите историю:

```bash
git log --oneline
```

### Результат

В репозитории должен находиться первый commit проекта.

---

# Упражнение 2. Разработка первой функциональности

В первой версии необходимо реализовать точку.

Создайте отдельную ветку:

```bash
git switch -c feature/point
```

В этой ветке:

1. создайте класс `Point`;
2. реализуйте необходимые свойства;
3. реализуйте отображение точки;
4. добавьте тесты;
5. обновите документацию.

Сделайте несколько осмысленных commits.

Например:

```text
Create Point class
Implement Point drawing
Add Point tests
```

Просмотрите историю:

```bash
git log --oneline --graph --all
```

### Вопрос

Почему разработку `Point` выполняли в отдельной ветке, а не непосредственно в `main`?

---

# Упражнение 3. Завершение функциональности

После завершения разработки убедитесь, что:

- проект собирается;
- тесты проходят;
- функциональность работает;
- документация обновлена.

Создайте Pull Request для ветки `feature/point`.

Перед слиянием выполните Code Review.

Проверьте:

- соответствие требованиям;
- качество кода;
- наличие тестов;
- отсутствие лишних изменений.

После проверки объедините ветку с `main`.

---

# Упражнение 4. Вторая функциональность

Теперь необходимо реализовать круг.

Создайте отдельную ветку:

```bash
git switch -c feature/circle
```

Реализуйте:

- класс `Circle`;
- отображение круга;
- необходимые тесты.

Сделайте commits и создайте Pull Request.

После проверки объедините ветку с `main`.

Проверьте историю:

```bash
git log --oneline --graph --all
```

# Упражнение 5. Параллельная разработка

Представим, что две задачи выполняются одновременно.

Один разработчик реализует квадрат:

```bash
git switch -c feature/square
```

Другой разработчик в своей ветке изменяет пользовательский интерфейс редактора:

```bash
git switch -c feature/tools
```

Каждый разработчик должен:

1. изменить код;
2. сделать commits;
3. проверить работу своей функциональности;
4. подготовить Pull Request.

В результате ветки должны развиваться независимо:

```text
                 feature/square
                /
main ──────────●────────●
                \
                 feature/tools
```

# Упражнение 6. Слияние изменений

Объедините одну из веток с `main`.

После слияния обновите вторую ветку относительно актуального состояния `main`.

Просмотрите историю:

```bash
git log --oneline --graph --all
```

Обратите внимание на то, как изменилась структура истории.

# Упражнение 7. Создание конфликта

Теперь специально создайте ситуацию, в которой два разработчика изменяют одну и ту же строку.

Например, в `README.md` обе ветки должны изменить описание текущей версии редактора.

В `feature/square` запишите:

```text
Реализованы точка, круг и квадрат.
```

В `feature/tools` запишите другую версию этой же строки:

```text
Добавлены инструменты создания графических элементов.
```

Сначала объедините одну ветку с `main`.

Затем попробуйте объединить вторую:

```bash
git merge feature/tools
```

Git должен сообщить о конфликте.

Проверьте состояние:

```bash
git status
```

# Упражнение 8. Разрешение конфликта

Откройте файл, в котором возник конфликт.

Git обозначит конфликт примерно так:

```text
<<<<<<< HEAD
Реализованы точка, круг и квадрат.
=======
Добавлены инструменты создания графических элементов.
>>>>>>> feature/tools
```

Самостоятельно определите итоговое содержимое файла.

В результате README должен содержать информацию **об обеих функциональностях**.

После исправления:

```bash
git add .
git commit
```

Проверьте историю:

```bash
git log --oneline --graph --all
```

### Вопрос

Почему Git не может автоматически определить, какой вариант текста необходимо оставить?

# Упражнение 9. Работа с готовой историей

Выполните:

```bash
git log --oneline --graph --all
```

Определите:

1. где находится `main`;
2. где находились созданные вами ветки;
3. какие commits относятся к каждой функциональности;
4. какой commit является результатом слияния.

Нарисуйте историю проекта на бумаге или в UML/графическом редакторе:

```text
              ● Point
             /
●───────────●──────────● main
             \        /
              ●──────●
                Circle
```

Фактическая схема должна соответствовать истории вашего репозитория.

# Упражнение 10. Итоговая разработка первого инкремента

Используя полученные навыки, реализуйте оставшуюся функциональность первого инкремента.

Для каждой функциональности:

```text
feature/...
      ↓
реализация
      ↓
тесты
      ↓
commit
      ↓
Pull Request
      ↓
Code Review
      ↓
merge
```

Минимальный набор веток:

```text
feature/point
feature/circle
feature/square
feature/factory
```

При необходимости отдельными ветками могут разрабатываться:

```text
feature/mouse-drawing
feature/canvas
feature/tests
```

# Результат практики

В результате работы в репозитории должна быть видна история разработки первого инкремента:

```text
                         feature/point
                        /
main ─────●────────────●────────────●────────────
                                      \
                                       feature/circle
                                        \
                                         ●───────
```

История должна показывать, что функциональности разрабатывались независимо, а затем объединялись в основную ветку.
