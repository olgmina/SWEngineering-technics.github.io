# Настройка git

*Информация о пользователе для всех локальных репозиториев*

```$ git config --global user.name "[name]"```

Устанавливает имя, которое вы хотите прикрепить к своим транзакциям фиксации

```$ git config --global user.email "[email address]"```

Устанавливает адрес электронной почты, который вы хотите прикрепить к своим транзакциям фиксации

```$ git config --global color.ui auto```
 
 Включает полезную раскраску вывода командной строки

## Ветви

*Ветки — важная часть работы с Git. Любые сделанные вами коммиты будут сделаны в той ветке, на которую вы в данный момент «зарегистрированы». Используйте git status, чтобы увидеть, какая это ветвь.*

| Команда | действие |
|------------------------| --------|
|```$ git branch [branch-name]```| Создает новую ветку |
|``$ git switch -c [branch-name]``|Переключается на указанную ветку и обновляет рабочий каталог|
|``$ git merge [branch]``| Объединяет историю указанной ветки в текущую ветку. Обычно это делается в запросах на вытягивание, но это важная операция Git.|
|``$ git branch -d [branch-name]``| Удаляет указанную ветку |

## Создание репозиториев

*Новый репозиторий можно создать локально или клонировать существующий репозиторий. Когда репозиторий был инициализирован локально, вы должны впоследствии отправить его на GitHub.*

| Команда | действие |
|------------------------| --------|
| ``$ git init`` | Команда git init превращает существующий каталог в новый репозиторий Git внутри папки, в которой вы запускаете эту команду. После использования git initкоманды свяжите локальный репозиторий с пустым репозиторием GitHub, используя следующую команду:
| ``$ git remote add origin [url]`` | Указывает удаленный репозиторий для вашего локального репозитория. URL-адрес указывает на репозиторий на GitHub.
| ``$ git clone [url]`` | Клонировать (скачать) репозиторий, который уже существует на GitHub, включая все файлы, ветки и коммиты.

## Файл .gitignore
*Иногда может быть хорошей идеей исключить файлы из отслеживания с помощью Git. Обычно это делается в специальном файле с именем .gitignore. Вы можете найти полезные шаблоны для .gitignoreфайлов на github.com/github/gitignore .*

## Синхронизировать изменения
*Синхронизируйте локальный репозиторий с удаленным репозиторием на GitHub.com*

```$ git fetch``` - Загружает всю историю из веток удаленного отслеживания

```$ git merge``` - Объединяет ветки удаленного отслеживания в текущую локальную ветку

```$ git push``` - Загружает все коммиты локальной ветки на GitHub

```$ git pull``` - Обновляет текущую локальную рабочую ветку всеми новыми коммитами из соответствующей удаленной ветки на GitHub. git pullпредставляет собой сочетание git fetchиgit merge

##Внесение изменений

*Просматривайте и проверяйте эволюцию файлов проекта*

```$ git log``` - Отображает историю версий для текущей ветки.

```$ git log --follow [file]``` - Отображает историю версий для файла, помимо переименований (работает только для одного файла).

```$ git diff [first-branch]...[second-branch]``` - Показывает различия в содержании между двумя ветвями

```$ git show [commit]``` - Выводит метаданные и изменения содержимого указанной фиксации

```$ git add [file]``` - Делает снимки файла в процессе подготовки к версии

```$ git commit -m "[descriptive message]"``` - Постоянно записывает снимки файлов в историю версий

## Повторение коммитов

*Стереть ошибки и создать историю замены*

```$ git reset [commit]``` - Отменяет все коммиты после [commit], сохраняя изменения локально

```$ git reset --hard [commit]``` - Отбрасывает всю историю и возвращается к указанной фиксации

**ОСТОРОЖНОСТЬ!** Изменение истории может иметь неприятные побочные эффекты. Если вам нужно изменить коммиты, существующие на GitHub (удаленно), действуйте с осторожностью. Если вам нужна помощь, обратитесь на github.community или в службу поддержки.

##Глоссарий

•	*git* : распределенная система контроля версий с открытым исходным кодом.

•	*GitHub* : платформа для размещения и совместной работы над репозиториями Git.

•	*commit* : объект Git, снимок всего вашего репозитория, сжатый в SHA

•	*Branch* : легкий подвижный указатель на фиксацию

•	*clone* : локальная версия репозитория, включая все коммиты и ветки.

•	*remote* : общий репозиторий на GitHub, который все члены команды используют для обмена своими изменениями.

•	*fork* : копия репозитория на GitHub, принадлежащая другому пользователю

•	*pull request* : место для сравнения и обсуждения различий, представленных в ветке, с обзорами, комментариями, интегрированными тестами и т. д.

•	*HEAD* : представляет ваш текущий рабочий каталог, указатель HEAD можно перемещать в разные ветки, теги или коммиты при использованииgit switch
