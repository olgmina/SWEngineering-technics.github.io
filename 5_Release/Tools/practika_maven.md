# Практика. Внедрение системы автоматизации сборки Maven


*Цель* Научиться переводить проект на декларативную систему сборки, управлять внешними зависимостями программного продукта, внедрять библиотеки сериализации и использовать современные средства метапрограммирования для снижения зацепления (coupling) и объема шаблонного кода (boilerplate).


>Процесс сборки, управления внешними библиотеками и компиляции должен быть полностью независим от среды разработки (IDE) и описан в виде кода.

## 1. Знакомство с Apache Maven

До третьего инкремента сборка проекта выполнялась средствами встроенного компилятора вашей среды разработки (IntelliJ IDEA, Eclipse, VS Code). Это создавало жесткую привязку к локальным настройкам компьютера разработчика.
Apache Maven — это инструмент автоматизации сборки проектов, управления зависимостями и жизненным циклом ПО. Он позволяет стандартизировать проект, декларативно описать, какие библиотеки ему нужны для работы и тестирования, и гарантирует, что код соберется одинаково на любой машине или сервере CI/CD.

Ключевые концепции

• Координаты артефакта: Каждый проект в экосистеме Maven уникально идентифицируется тройкой: groupId (кто создал, например, домен организации), artifactId (название программы) и version (версия).
• Репозитории: Maven скачивает сторонние библиотеки автоматически из глобального хранилища (Maven Central) и кеширует их в локальном репозитории пользователя на диске (папка .m2/repository).
• Жизненный цикл (Lifecycle): Состоит из фаз: validate -> compile -> test -> package (сборка JAR) -> verify -> install (публикация локально).

## 2. Обзор стандартной структуры проекта Maven

Maven накладывает строгое соглашение о конфигурации (Convention over Configuration). Проект больше не может хранить файлы в произвольных каталогах.

Стандартная топология каталогов

Проверьте и перестройте структуру папок вашего репозитория GraphEditor в соответствии со стандартом:
GraphEditor/
├── src/
│   ├── main/
│   │   ├── java/         <-- Исходный код приложения (пакеты org.example...)
│   │   └── resources/    <-- Конфигурационные файлы, иконки UI, файлы настроек
│   └── test/
│       ├── java/         <-- Исходный код модульных и интеграционных тестов
│       └── resources/    <-- Тестовые файлы (например, поврежденные файлы для тестов)
├── docs/                 <-- Документация (остается на прежнем месте)
├── pom.xml               <-- Главный конфигурационный файл Maven (в корне проекта)
├── CHANGELOG.md
└── .gitignore

## Задание 2 Переход к управлению проектом

1. Найдите в корне проекта файл pom.xml.

Файл pom.xml — это декларативное сердце проекта в формате XML. Он управляет компиляцией, плагинами и областями видимости зависимостей.

Области видимости зависимостей (<scope>)

Важнейший элемент управления качеством — изоляция библиотек по фазам использования:
• compile (по умолчанию): Зависимость нужна всегда (и при написании кода, и при запуске).
• test: Библиотека нужна исключительно для компиляции и запуска тестов (например, JUnit). В финальную сборку программы она не попадет.
• provided: Библиотека нужна для компиляции, но в рантайме ее предоставит среда исполнения или плагин (например, Lombok).

2. Выявите:
 - основные элементы проекта: имя продукта, номер версии, используемый стандарт языка и компилятора
 - Подключенные зависимости: Какие внешние библиотеки уже объявлены в проекте? Укажите их назначение.
 - Включенные этапы сборки:  Какие фазы жизненного цикла (Lifecycle) будут затронуты при выполнении команды mvn clean package? Укажите, какие встроенные плагины Maven будут отвечать за этап компиляции (compile) и этап тестирования (test).



### Задание 3 Подключение библиотеки для работы с JSON

В соответствии с новыми архитектурными требованиями Инкремента 3, процесс трансляции рисунка должен быть изолирован с помощью паттерна Строитель (GoF Builder), а сохраняемый формат должен поддерживать структурированный JSON. Для этого нам необходим промышленный инструмент сериализации — Jackson Databind.

Задание

1. Откройте pom.xml и добавьте внутрь тега <dependencies> координату библиотеки Jackson:
```xml
   <dependency>
       <groupId>com.fasterxml.jackson.core</groupId>
       <artifactId>jackson-databind</artifactId>
       <version>2.17.2</version>
   </dependency>
```

2. Выполните команду обновления зависимостей в вашей IDE или через консоль
```bash
mvn clean compile
```

3. Реализуйте класс JsonDrawingBuilder, импортировав класс com.fasterxml.jackson.databind.ObjectMapper. Конкретный строитель должен пошагово собирать JSON-структуру графических примитивов при обходе холста Директором.
