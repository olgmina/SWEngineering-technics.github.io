# Локализация приложения как адаптация приложения к различным языкам и регионам для удобства пользователя

(термин интернационализация, или i18n -

Ключевой принцип  — это минимизация изменений кода и исключение необходимости компиляции при добавлении поддержки новых языков или регионов.  Это достигается за счет отделения текстовых ресурсов (и других локализуемых данных) от исходного кода.

В Java наиболее распространенным способом достижения этого является использование ресурсов, таких как файлы свойств (`.properties`) и классы `ResourceBundle`.  Эти ресурсы загружаются во время выполнения, позволяя изменять локализованный контент без перекомпиляции приложения.


## Пример  локализации

Класс `ResourceBundle`:

`ResourceBundle` — это основной класс Java для доступа к локализованным ресурсам. Он использует механизм связывания, основанный на локали (Locale), которая определяет язык и регион (например, `ru_RU` для русского языка в России, `en_US` для американского английского).

Файлы свойств, используемые `ResourceBundle`, имеют структуру "ключ=значение", где ключ — это идентификатор текста, а значение — его перевод на конкретный язык.  Например, файл `messages_ru_RU.properties` может содержать:

```properties
greeting=Здравствуйте!
farewell=До свидания!
```

а файл `messages_en_US.properties` :

```properties
greeting=Hello!
farewell=Goodbye!
```

Для доступа к ресурсам:

```java
import java.util.Locale;
import java.util.ResourceBundle;

public class LocalizationExample {
    public static void main(String[] args) {
        // Установка локали
        Locale locale = Locale.getDefault(); // Или Locale.forLanguageTag("ru_RU");
        ResourceBundle messages = ResourceBundle.getBundle("messages", locale);

        // Доступ к локализованным строкам
        String greeting = messages.getString("greeting");
        String farewell = messages.getString("farewell");

        System.out.println(greeting);
        System.out.println(farewell);
    }
}
```
